# Handoff — April 2, 2026

## What Was Done Today

### 1. Fixed Frontend Down — `Unexpected token '<'` (nginx 502)
**Root cause**: Nginx config on production had **hardcoded container IPs** (`172.18.1.12` for backend). When containers restarted during deploys, they got new IPs (e.g. `172.18.1.2`). Nginx kept pointing to stale IPs → 502 Bad Gateway → browser got HTML instead of JSON → `Unexpected token '<'`.

**Fix**:
- `infra/nginx/nginx.conf` — now uses Docker **service names** (`backend-api`, `frontend`) instead of IPs
- Nginx is now managed inside `docker-compose.yml` on the server (same network, service discovery works)
- Server compose file updated from v61 → v62, all containers recreated on correct `ronexa_net`

### 2. Fixed `'PortalSession' object has no attribute 'api'`
**Root cause**: Two session types exist — `PortalSession` (browser lifecycle dataclass in `browser_manager.py`) and `PlaywrightPortalSession` (with `.api()` method in `session.py`). The ephemeral browser refactor created the new `PortalSession` but `http_server.py` passed it raw to the compiler, which expects `PlaywrightPortalSession`.

**Fix**: Added `_to_portal_session()` bridge in `backend/app/worker/http_server.py` that wraps `PortalSession` → `PlaywrightPortalSession` before passing to compiler. Applied to both `process_case` and `finalize_case`.

### 3. Deploy Script (`deploy.sh`) — Major Improvements
- **Fixed exit code 1** in status mode (`set -euo pipefail` + grep returning 1 on no match)
- **Workers now deploy via SCP + SSH** — `az vm run-command` was silently failing for large base64 payloads
- **Worker health checks use SSH** too
- **Added `./deploy.sh restart`** — quick container restart + nginx config refresh (no rebuild)
- **Health check now includes `Nginx→API`** line — catches routing issues early
- **`sync_configs()`** pushes nginx.conf to server on every deploy
- **`deploy_orch()`** updates compose tags via `sed` on server, verifies nginx routing after deploy
- **Change detection** now includes `infra/nginx` changes

### 4. Production Compose File Alignment
- `docker-compose.prod.yml` rewritten to match server's actual setup (static IP network `ronexa_net`, `172.18.1.0/24`)
- Server uses `docker-compose.yml` (not `docker-compose.prod.yml`) — deploy script handles this
