### 2. Toggle Worker Fix (v44)
- `POST /settings/workers/{id}/toggle` now sends `request_stop` to Restate + sets `stop_requested=True` when deactivating
- Previously only flipped `is_active` in DB — running WorkerLoop wouldn't stop

### 3. WorkerLoop: workflow_call → workflow_send (v41)
- **Root cause**: `ctx.workflow_call()` blocked the WorkerLoop until CaseWorkflow completed — including review suspension. Both workers stalled after ~3 cases each waiting for rep review.
- **Fix**: Changed to `ctx.workflow_send()` (fire-and-forget) with 10-second throttle between dispatches
- Workers now dispatch continuously without blocking on reviews
- CaseWorkflow manages its own lifecycle (review → finalize → submit)

### 4. PENDING_STAT Cases Now Claimable (v42)
- `claim_next_job()` only looked for `Case.state == NOTES_UPLOADED`
- STAT cases had `state=PENDING_STAT` and were never claimed despite having priority=1000
- **Fix**: Added `PENDING_STAT` to the claim filter

### 5. Clinical Scenario (Pathway Question) Always Stored (v43)
- Previously gated by `if pathway_data.get("pathway_options"):` — some cases didn't get the pathway question
- Removed the guard — `_pathway_decision` is now always stored in `context_vars`
- Added fallback: if `pathway_options` is empty, builds single-option from selected pathway
- Added debug logging for `_pathway_decision` presence in question loop

### 6. Auto-Fill Noise Removed (v43)
- Hidden questions (DOB, Client Id, CPT Code — `ForDisplay=False`) were being saved as review questions
- Reps saw 1% confidence noise questions that the portal auto-fills
- **Fix**: Hidden auto-fills stay in the accumulator (needed for portal API) but are NOT added to `all_decisions` (review UI)

### 7. Facility Search Timeout Fix (v44)
- HAR showed `hdnAction=6` page transition takes 25-35 seconds
- Our timeout was 10 seconds → cases failed at facility search
- **Fix**: Increased to 45s primary + 15s retry after `domcontentloaded`

### 8. Finalize HOLD Detection (v44)
- `finalize_case` and `replay_case` in `http_server.py` always called `mark_case_complete` even when compiler returned `case_state=HOLD`
- Case showed as "submitted" in UI but actually failed (e.g., Zoe Grimaldo facility timeout)
- **Fix**: Check `result.get("case_state") == "HOLD"` before marking complete, properly route to `mark_case_hold`

### 9. L2 Review: L1 Note + Rerun Button (v45-v48)
- **L1 Note visible to L2**: Added `l1_note` column to Question model (migration 015). When L1 edits a question and provides a reason, it's stored on that specific question and displayed in L2 view with "L1 Note:" badge.
- **Rerun button always enabled**: Removed `!hasEdits` disabled condition — L2 can always initiate a rerun.
- **Value comparison fix (v47-v48)**: `_apply_review()` was comparing `ai_answer.get("Value")` but portal format uses `"Values"` (plural list). Created `_extract_value()` helper that handles both formats. Added `_values_equal()` for order-independent list comparison and None/empty equivalence.
- **Frontend `getAiValue` fix (v35)**: Dict-shaped auto-fill answers (MeasureUnitValues etc.) were being sent as objects → 422 validation error. Now returns `""` for non-string/non-list answers.
- **Error display fix (v34)**: FastAPI 422 errors with array `detail` showed as `[object Object]`. Now properly stringifies validation messages.

### 10. Worker VM Code Deploy Pattern Established
- Workers run bare Python (systemd service), not Docker
- No git on worker VMs — code deployed via SCP from orchestrator
- Pattern: extract files from v44 container → temp HTTP server on orchestrator (:9999) → workers curl + restart
- Must restart workers after code changes to `http_server.py`, `webforms_client.py`, `portal_compiler.py`
