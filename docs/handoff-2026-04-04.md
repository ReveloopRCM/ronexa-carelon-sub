# Handoff — April 4, 2026

## Major Discovery: IsExamAutoApproved Is a UI Flag, Not the Approval Decision

We've been treating `IsExamAutoApproved` as the portal's final verdict on whether a case is approved. **It's not.** It's a UI routing flag that controls whether the portal shows CDO (Clinical Decision Override) and AddFeedback forms during the clinical entry flow.

### Evidence

1. **www.providerportal HAR** (in `Auth Approved/` folder) — `IsExamAutoApproved` returned "N", CDO + AddFeedback were called, case was submitted, and it ended up **approved**.

2. **Reference implementation** (`carelon-sub/submission_flow.py` lines 422-427) — calls `is_exam_auto_approved()` and `is_exam_cdo()` but **discards both return values**. Always proceeds to AddFeedback and Submit unconditionally.

3. **Our GPAWV responses** already show `RecommendationType: 3` (Approve) — the clinical algorithm IS approving our answers. The "N" on IsExamAutoApproved was a red herring.

4. **Two behavioral patterns in approved HARs**:
   - Pattern A (IsExamAutoApproved=Y): ProcessAccepted → IsExamAutoApproved → AddRadioTracers (skips CDO/AddFeedback)
   - Pattern B (IsExamAutoApproved=N): ProcessAccepted → IsExamAutoApproved → CDO → AddFeedback → AddRadioTracers
   - Both patterns proceed to submission and can result in approval

### The Real Approval Signal

The **clinical algorithm's `RecommendationType`** from the last `GetPathwayAssetsWithValidation` response is the actual recommendation:
- `RecommendationType: 3` = **Approve** (algorithm recommends approval)
- `RecommendationType: 6` = In Progress (still answering questions)

The final determination (approved/pended/denied) comes from the **post-submit confirmation page** text, parsed after clicking "Submit This Request."

## Code Changes

### 1. `backend/app/portal/clinical_flow.py`

**Algorithm capture**: Every GPAWV response now captures `RecommendationType`, `ExamResult`, `ExamOutcome` into instance vars (`_algorithm_recommendation`, `_exam_result`, `_exam_outcome`).

**finalize()**: No longer branches on IsExamAutoApproved. Always calls CDO + AddFeedback unconditionally (matching reference implementation). Returns enriched result:
```python
{
    "auto_approved": is_auto,          # IsExamAutoApproved (UI flag)
    "cdo_approved": is_cdo,
    "algorithm_approved": True/False,  # RecommendationType == 3 (THE REAL SIGNAL)
    "algorithm_recommendation": 3,     # Raw RecommendationType value
    "exam_result": 1,
    "exam_outcome": "C",
}
```

**probe_approval()**: Same enriched return with algorithm fields.

### 2. `backend/app/compiler/portal_compiler.py`

Probe result now maps `algorithm_approved` → `result["auto_approved"]` for storage on Case model:
```python
result["auto_approved"] = probe_data.get("algorithm_approved")  # THE REAL SIGNAL
result["is_exam_auto_approved"] = probe_data.get("auto_approved")  # UI flag, diagnostic only
```

### 3. `backend/tests/test_portal_live.py`

- **Fixed Q3 override bug**: Was setting `answers[i]["answer_value"]` (LLM internal field) instead of `answers[i]["Values"]` (portal field). Override never actually changed what was sent to the portal.
- Updated determination logging to show algorithm verdict prominently.

## Hypothesis Test Results

### Weakness Branch Hypothesis: **Disproven**

We hypothesized that selecting "Weakness (motor deficit)" in Q3 instead of "Reflex abnormality" would flip IsExamAutoApproved to Y (based on Dumas approved HAR comparison). Ran George (CPT 72148) with forced weakness override:

- Override correctly changed portal flow (got motor/sensory deficit questions instead of reflex questions)
- IsExamAutoApproved still returned "N"
- **But**: RecommendationType was already 3 (Approve) — the "N" doesn't matter

The weakness vs reflex selection changes the question branch but doesn't affect the algorithm's approval recommendation. Both branches can lead to RecommendationType=3.

## Impact

Cases in production that were marked `auto_approved=False` were likely algorithm-approved all along. With this fix:
- `case.auto_approved` now reflects the algorithm's recommendation (True when RecommendationType=3)
- `case.approval_type = "algorithm"` when algorithm approves
- Frontend verdict banner will correctly show green "Algorithm Approved"
- **No change to actual submission behavior** — submissions already proceed regardless
